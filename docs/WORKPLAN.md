# 可视化强化学习教学网站 · 工作文档

> 版本：v0.2（2026-09-03）
> 本文档是项目的唯一事实来源（Single Source of Truth）。里程碑完成后更新状态勾选；决策确认后回填第 8 节。

---

## 1. 项目定位

**一句话描述**：一个纯前端的强化学习（RL）交互式教学网站，让有编程基础的学习者通过"看得见的算法"和"玩得起来的实验场"建立对经典与深度强化学习的直觉理解。

**目标受众**：有 Python/编程基础、但未系统接触过 RL 的学习者（大学生、转行者、工程师）。假设读者会写代码，不假设读者有机器学习背景。

**核心理念**：

1. **直觉优先**：每个概念先用可视化和类比建立直觉，再给出公式（公式用 KaTeX 渲染，作为"精确化"而非起点）。
2. **可动手**：关键算法都配实验场——用户可调参数（学习率、探索率、折扣因子等）、实时观察训练过程与曲线、亲手单步控制智能体。
3. **可复现**：所有实验支持固定随机种子、参数写入 URL，方便分享和课堂演示。
4. **算法即教材**：算法实现本身就是教学素材——代码保持干净、带注释、与 UI 完全解耦，鼓励学习者读源码。

**明确不做的事**（范围边界）：

- 不做用户系统/云同步（学习进度仅存 localStorage）。
- 不追求大规模训练（浏览器内训练限定 CartPole/Pendulum 量级的任务）。
- 第一版不做移动端专门优化（保证不崩、可浏览即可，M5 再打磨）。

## 2. 内容规划（章节大纲）

共 8 个正式章节 + 1 个进阶议题池，分两个阶段交付。每章结构统一为：**引入（为什么需要它）→ 直觉与可视化 → 数学形式化 → 算法伪代码 → 实验场 → 小结与常见误区**。

|---|------|-----------|--------------|--------|

| 1 | 多臂老虎机：探索与利用 | ε-greedy、探索-利用困境、regret 直觉 | 拉老虎机模拟器：实时收益曲线、ε 滑块、不同策略对比 | M2 |
| 2 | 马尔可夫决策过程（MDP） | 状态/动作/奖励/转移、回报 G、折扣因子 γ、价值函数 V/Q、贝尔曼方程 | GridWorld 世界观介绍；γ 滑块实时改变价值热力图与最优路径 | M2 |
| 3 | 动态规划 | 策略迭代、价值迭代、自举（bootstrapping）思想 | 价值迭代收敛动画：热力图逐轮变化 + 策略箭头演化；可调收敛阈值 | M2 |

| 5 | Q-Learning 与 SARSA | Q 表、ε-greedy 策略、on-policy vs off-policy、收敛性 | **核心实验场**：GridWorld / Cliff Walking 训练器（详见 3.2） | M2 |

## 3. 交互与可视化设计

### 3.1 三类交互形态

| 形态 | 说明 | 例子 |
|------|------|------|
| **概念动画** | 预设脚本的动画，支持播放/暂停/单步/调速，用于讲直觉 | Agent-Env 循环、MC vs TD 对比 |
| **参数化演示** | 用户调 1-2 个参数，立即看到结果变化，用于理解单一变量的影响 | γ 滑块改价值热力图、clip-ε 交互图 |
| **训练实验场** | 完整训练循环，用户配置超参、启动训练、观察曲线与环境表现，用于建立"炼丹"手感 | Q-Learning 实验场、DQN/PPO 训练器 |

### 3.2 核心实验场设计

**Q-Learning / SARSA 实验场（M2 旗舰组件）**

- 环境：GridWorld（可切换 Cliff Walking 布局），Canvas 渲染。
- 画布分层：格子底色 = V/Q 值热力图；叠加层 = 最优策略箭头；智能体 + 最近 N 条轨迹渐隐尾迹。
- 控制面板：算法（Q-Learning / SARSA / 对比模式）、α、ε（含衰减开关）、γ、训练速度（1x ~ 1000x / 单步 / 暂停）、随机种子、重置。
- 数据面板：episode 回报曲线、ε 当前值、平均回报收敛指示。
- 对比模式：左右分屏跑两个算法（如 SARSA vs Q-Learning 走悬崖），同种子对齐对比。

**DQN / PPO 训练器（M3/M4）**

- 训练循环跑在 Web Worker，主线程只收聚合指标，保证 UI 流畅。
- 环境：CartPole（自研 TS 物理实现，与 OpenAI Gymnasium 公式一致）、Pendulum（PPO 章）。
- 可视化：实时 reward/loss 曲线、MLP 网络图（节点按激活强度着色）、Replay Buffer 采样示意、ε 调度。
- 性能兜底：预置若干不同训练时长价位的"预训练检查点"，用户可先看结果再决定是否从头训。

### 3.3 通用交互组件库（一次开发、各章复用）

| 组件 | 功能 |
|------|------|
| `PlaybackControls` | 播放/暂停/单步/速度/重置/种子，统一所有演示的操控习惯 |
| `ParamPanel` | 超参滑块组（含数值输入、预设方案、URL 同步） |
| `GridWorldRenderer` | Canvas 网格世界：热力图、策略箭头、轨迹、智能体动画 |
| `LiveChart` | 实时滚动训练曲线（reward、loss、ε 等，对数轴可选） |
| `NetworkVisualizer` | MLP 结构图与激活热色 |
| `EpisodeLog` | 训练过程事件流（如"第 120 回合：最早达标"） |

## 4. 技术方案

### 4.1 总体架构

```
┌────────────────────── 浏览器 ──────────────────────┐
│                                                     │
│  章节页面 (MDX 文案 + React 交互组件)                 │
│        │                                            │
│  ┌─────▼──────┐   指标流    ┌──────────────────┐    │
│  │  UI 组件层  │◄───────────│  Web Worker       │    │
│  │ Canvas/图表 │            │  训练循环:         │    │
│  └────────────┘            │  rl-core 算法+环境 │    │
│                            └────────┬─────────┘    │
└─────────────────────────────────────┼──────────────┘
                                      │ 纯 TS，零 UI 依赖
                            ┌─────────▼─────────┐
                            │     rl-core        │
                            │ env/ algo/ nn/ seed│
                            └───────────────────┘
```

### 4.2 技术选型

| 领域 | 选择 | 理由 |
|------|------|------|
| 框架 | React 18 + TypeScript + Vite | 生态成熟；TS 类型利于教学代码可读性；Vite 开发体验好 |
| 内容 | MDX | 章节文案中直接嵌入交互组件，图文与代码一体化 |
| 样式 | Tailwind CSS | 快速搭建统一风格，避免手写大量 CSS |
| 渲染 | 原生 Canvas 2D | 教学场景规模小，无需 PixiJS/Three.js 重依赖 |
| 图表 | uPlot（倾向）或自研轻量图表 | 训练曲线需高频更新，uPlot 仅 ~40KB 且性能极佳；M1 时最终定夺 |
| 数学公式 | KaTeX | 轻量、渲染快，比 MathJax 适合多公式页面 |
| 状态管理 | zustand | 轻量，适合"实验场配置"这类局部共享状态 |
| RL 算法 | **自研 rl-core（纯 TS）** | 算法即教材；表格型方法无需深度学习框架；DQN/PPO 用自研微型 MLP（见 4.3） |
| 测试 | Vitest | 对 rl-core 做收敛性/回归测试（见 4.4） |
| 部署 | GitHub Pages（GitHub Actions 自动发布） | 免费零后端；项目页为子路径，Vite `base` 需设为 `/rl-playground/`，所有资源用相对引用 |

### 4.3 关键技术决策与说明

1. **不引入 TensorFlow.js**（首期）。CartPole 级任务的网络很小（如 4→64→2 的 MLP），自研微型 NN（TypedArray 前向/反向传播 + Adam）在 Worker 里 CPU 跑足够快，且反向传播代码本身可作教学素材。若 M3 实测性能不足，再评估引入 TF.js（预留接口：`rl-core/nn` 定义 `PolicyNetwork` 抽象）。
2. **训练全部进 Web Worker**。主线程只接收降采样后的指标（如每 10 episode 推一次），UI 永不卡顿。
3. **算法与 UI 严格解耦**。`rl-core` 不 import 任何 React/DOM；交互层只消费它的快照（`render(state)` 式数据），保证算法可单测、源码可读。
4. **可复现性**：自实现带种子的 PRNG（xoshiro/mulberry32），贯穿环境与算法；实验配置序列化进 URL query。

### 4.4 质量保障

- **算法正确性**：每个算法配固定种子的收敛性测试（如"Q-Learning 在 4x4 GridWorld 上 2000 episode 内平均回报 ≥ 阈值"），CI 跑 Vitest。
- **对拍验证**：DQN/PPO 实现与 Python 参考实现（Stable-Baselines3）在相同超参下对拍 reward 曲线形态，防"能跑但错"。
- **教学评审 checklist**：每章发布前过一遍——直觉先行？公式准确？实验默认参数能出好结果？术语中英对照齐全？

### 4.6 视觉设计规范（原神风配色）

设计基调：借原神 UI 的**"墨蓝描金"框架 + 羊皮纸阅读区**气质——页面框架（顶栏、导航、卡片描边、标题装饰）用墨蓝底描金；正文阅读区用米白羊皮纸底，保证长文阅读舒适度。

| Token | 值 | 用途 |
|-------|-----|------|
| 墨蓝 ink | `#3B4354` / `#495366` | 框架底色、标题文字 |
| 描金 gold | `#D3BC8E`（哑光）/ `#E0C386`（亮） | 描边、分隔线、装饰、hover |
| 羊皮纸 parchment | `#FAF6EE`（页面底）/ `#F4EEE1`（卡片底） | 阅读区背景 |
| 正文墨色 | `#3B4255`（主）/ `#6C7688`（次） | 文字 |
| 链接/强调金 | `#B8935A` | 链接、按钮主色（保证对比度） |
| 星级金 | `#FFD766` | 成就、完成标记 |
| 警示红 | `#DF5D57` | 错误、危险操作 |

**图表分类色板（借用七元素色，为算法/曲线分配"身份色"）**：

火 `#EF7938` · 水 `#4CC2F1` · 风 `#74C2AB` · 雷 `#AF6EC6` · 草 `#A5C83B` · 岩 `#F8B955` · 冰 `#9FD6E3`

示例分配（M1 定稿）：SARSA=火、Q-Learning=水、DQN=雷、REINFORCE=风、PPO=岩；章节导航点缀对应元素色。同一算法在全站（曲线、图例、章节标签）永远同色，降低认知负担。

**字体与装饰**：标题 Noto Serif SC（衬线感呼应游戏 UI），正文 Noto Sans SC / system-ui，公式 KaTeX 默认字体。装饰仅用 CSS 实现（金色细线、菱形 bullet、卡片圆角金描边）。

**版权红线**：只借鉴配色与气质，**不使用**原神的美术素材、图标、字体文件、角色形象，站名文案不出现"原神"字样。

## 6. 风险与对策

| 风险 | 影响 | 对策 |
|------|------|------|
| 浏览器内深度 RL 训练太慢/不收敛 | M3/M4 体验崩塌 | 小网络+Worker+降频；预训练检查点兜底；必要时引入 TF.js（4.3 已预留）；M3 第一周先做性能验证 spike |
| 自研算法"能跑但 subtly 错" | 教学错误，代价最高 | 固定种子收敛测试 + 与 SB3 对拍（4.4）；关键公式二次核对文献 |
| 范围蔓延（想加的内容越来越多） | 永远发布不了 | 进阶内容一律进议题池；里程碑外的新想法先记录不实施 |
| 章节文案质量不稳定 | 教学效果差 | 统一章节目录制（第 2 节）；发布 checklist |
| 纯前端看不到 Python 生态衔接 | 学习者迁移断层 | 每章末尾加"在真实项目中"小节：给出等价 Gymnasium/Stable-Baselines3 代码片段 |
